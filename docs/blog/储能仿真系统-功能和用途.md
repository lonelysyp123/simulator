## 它是什么：一座「开在电脑里」的示范电站

可以把本系统想象成：**在笔记本电脑或工控机上运行的一座小型虚拟储能电站**。  
里面有电池、变流器、变压器、开关、负载和并网侧的计量表计；它们会随时间变化——例如电池电量（荷电状态）会随充放电改变，功率不会瞬间跳变，而是像真实设备一样逐步爬升。

它的用途很直接：**在真机未到货、现场不能动、或需要反复试同一种工况时**，先用这座虚拟电站把流程跑通。

## 第一眼：主菜单里都能进哪里

程序启动并完成加载后，会进入**控制台里的图形化菜单**（使用方向键选择、回车进入）。主菜单通常包括这些入口：

- **主电气接线**：一站总览，最接近「站长想一眼看清的东西」。
- **电池堆簇信息 / 电池单体信息**：从整站电池到每一簇、甚至单体层面的数据，逐级下钻。
- **命令输入**：给熟悉调试的同事用，可输入预设好的操作语句（相当于站内「遥控口令」）。
- **连接信息**：查看外部调试软件是否已经连上、各服务是否在监听。
- **日志信息**：运行过程中的提示与告警，便于排查「为什么这次数不对」。

## 核心大屏：主电气接线在展示什么

进入「主电气接线」后，你会看到类似**运行监视大屏**的布局：断路器分合状态、主变压器与单元变压器两侧的电压电流、两台储能变流器的有功与无功、电池舱的直流电压与电流、站内计划负载、以及并网电表上的三相电压电流等。

很多团队会在这里做三件事：

1. **给领导或客户演示**：不解释协议细节，只展示「电站正在充/放电、表计在动」。
2. **和同事对齐口径**：大家指着同一块屏讨论「分闸之后功率应该去哪」。
3. **快速判断仿真是否健康**：若长时间全零或明显不合物理规律，可先回到配置与连接排查。

界面往往还支持在**表格视图**和**简易线路示意图**之间切换（例如使用键盘上的 Tab），方便录屏或投影。

## 电池视角：从「一整堆」看到「每一节」

真实电站里，电池是分堆、分簇、再分到模组与单体的。仿真里同样分层：

- **电池堆簇信息**：适合运维与能量管理同事，看各簇是否均衡、整体荷电状态大致如何。
- **电池单体信息**：适合对安全与一致性要求更高的场景，观察电压等细粒度曲线是否合理。

## 和外界对话：像连真设备一样连它

在工程现场，调度系统、能量管理系统、网关或专用调试软件，往往通过**工业上常见的 TCP 通讯与寄存器读写**，去读取电表、变流器、电池管理单元等设备的数据，并下发功率指令。

本仿真程序对外的使用方式与此**一致**：外部软件仍然用「连设备」的方式去连**本机上的不同通讯端口**——可以理解为**多台虚拟设备各占一个门牌号**，分别扮演并网电表、各单元的变流器侧、以及各套电池管理系统。这样，你的上位机程序**几乎不用改逻辑**，就能把仿真站当成调试对象。

## 站内能「演」哪些工况（用现象说话，不讲指令）

下面这些能力，读者从**界面数值变化**就能感知，不必知道背后如何实现：

| 你想演示或验证的现象 | 读者在画面里会看到什么 |
|----------------------|-------------------------|
| 充电 / 放电 | 电池荷电状态朝一个方向持续变化，变流器功率与直流电流符号与大小随之联动 |
| 功率不会瞬间跳满 | 给定新的出力目标后，有功或无功会**逐步爬升**到目标附近，而不是下一帧就顶格 |
| 站内负载变化 | 负载功率改变后，变压器与表计上的潮流随之重新分配 |
| 主开关分闸 / 合闸 | 断路器状态切换后，并网路径与部分功率显示会发生符合设计的改变 |
| 异常或保护 | 在越限场景下，设备可进入告警或停机类状态（具体以当前版本行为为准） |

进阶同事可以通过**命令输入**页，用程序支持的一小段文字命令，快速改功率、改负载、或演练分合闸；测试团队还可以把一串操作保存成**自动脚本**，每次一键重放，用来做回归或给客户看「可重复」的演示。

## 哪些角色会从这套工具里受益

| 角色 | 能获得的帮助 |
|------|----------------|
| 能量管理 / 调度策略同事 | 在接近真实的功率响应下，验证策略是否按预期动作，而不必等真机排期 |
| 通讯与集成同事 | 用与现场一致的读写方式联调，提前暴露地址、缩放、轮询周期等问题 |
| 测试与质量同事 | 固定脚本重复跑同一工况，减少「人工点十次十次不一样」的偶然性 |
| 培训与市场同事 | 用一块屏讲清储能站在稳态与动态下「各表计在怎样联动」 |
